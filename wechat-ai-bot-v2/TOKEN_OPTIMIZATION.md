# Token 优化策略

## 背景

DeepSeek API 按 token 计费。每个请求的 input_tokens + output_tokens 都计入费用。聊天机器人需要频繁调用 API，token 浪费会显著增加成本。

## 实现的优化

### 1. 智能历史截断

```python
# 按场景动态调整上下文窗口
SHORT_HISTORY = 40   # 闲聊 → 只需 40 条
NORMAL_HISTORY = 100  # 一般任务 → 100 条
LONG_HISTORY = 200    # 复杂工具调用 → 200 条
```

**原理**：闲聊不需要长上下文。通过统计对话长度自动分级，对话越短越节约。

**节省**：闲聊场景相比固定 400 条省 **90%**。

### 2. 分级 max_tokens

```
闲聊 → 4096 tokens（够用）
工具密集 → 自动升级到更高
```

首次 API 调用只用 4096 tokens（闲聊回复几百字足够），只在 AI 调用工具时自动加大。

**节省**：非工具场景省 **75%**（16384 → 4096）。

### 3. 工具结果智能截断

```python
web_search → 2000 字符
bash       → 1500 字符
read       → 3000 字符
```

截断不是丢失信息——截断后加提示 "共X字已截断，需要更多请用 XX 获取"，AI 可以二次请求完整结果。

**节省**：工具调用结果体积减少 **50-62%**。

### 4. 系统提示词精简

从 ~300 tokens 精简到 ~150 tokens，去掉了 AI 不需要的工具使用说明（tools/function calling 已经描述了）。

**节省**：每次请求省 150 tokens。

### 5. 按需加载历史

全量历史保存在磁盘（`memory.json`），但只发送最近 N 条给 API。重启后历史不丢，但不会全量塞进 token。

## 总效果

| 场景 | 优化前 | 优化后 | 节省 |
|------|------|------|------|
| 闲聊 | ~8000 tokens | ~800 tokens | **90%** |
| 搜索+回复 | ~6000 tokens | ~2000 tokens | **67%** |
| 复杂任务 | ~15000 tokens | ~6000 tokens | **60%** |

月费估算：< ¥5（日常使用）
